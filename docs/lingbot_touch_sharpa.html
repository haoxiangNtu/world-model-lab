第 7 节：同一个任务，两个仿真器：Sharpa 手拧瓶盖在 Isaac Sim 和 mortar 里

这一节做什么：把 PhysX 里瓶盖各不相同的拧瓶盖任务在 mortar 里重做一份（同一只 Sharpa 手、同样的任务规则和训练代码），比较训练速度、训练出的成功率，以及策略换仿真器后还剩多少。
结果：两边各 17 次训练都已完成（11-22）。在各自的仿真器里，盖子转满一圈的比例：不给触觉 PhysX 71.2–81.6 %、mortar 75.3–88.9 %，二值接触 PhysX 85.4–96.5 %、mortar 85.9–91.9 %，原始触觉 PhysX 90.0–96.1 %、mortar 67.8–93.2 %，CNN PhysX 88.2–93.8 %、mortar 85.9–94.6 %；mortar 已评测的 17 次里有 3 次拧开后不提盖子。训练速度 mortar 比 PhysX 慢约 6.4 倍（3000 万步 2.6–3.0 小时对 25–27 分钟）。策略原样换到另一个仿真器，两个方向都掉得多：PhysX 训练的放进 mortar 是 2.7–64.9 %，mortar 训练的放进 PhysX 是 1.1–62.6 %。

做了什么：“PhysX 拧瓶盖”一节里瓶盖各不相同的那一版，在 mortar 里重做了一份：同一只 Sharpa 手（22 个关节，质量、关节参数、碰撞外形和指尖软垫的位置都取自同一份模型文件）、同样的 27 种瓶盖和螺纹规则、同样的观测、动作、奖励、重置和结束条件，训练代码和超参数也是同一份（4104 个并行环境，每次 3000 万步）。两边的策略网络输入输出完全相同，所以一边训练出的策略可以直接放到另一边运行。比较三件事：训练速度、训练出的成功率、策略换仿真器后还剩多少。

结果（11-22）：两边各 17 次训练都已完成（不给触觉 5 个种子，二值接触 4 个种子，原始触觉 4 个种子，CNN 4 个种子），每次 3000 万步。成功率（盖子转满一圈）：不给触觉时 PhysX 71.2–81.6 %、mortar 75.3–88.9 %；三种有触觉的输入 PhysX 85.4–96.5 %、mortar 67.8–94.6 %。速度：mortar 比 PhysX 慢约 6.4 倍，3000 万步 PhysX 用 25–27 分钟，mortar 用 2.6–3.0 小时。换仿真器：PhysX 训练的策略原样放进 mortar，不给触觉的还能转满一圈的占 33.9–64.9 %，直接读触觉数值的两种只剩 2.7–50.5 %；mortar 训练的策略放进 PhysX，不给触觉的是 3.0–47.1 %，有触觉的三种是 1.1–62.6 %。

这张表里的 PhysX 是为这次对比重新训练的：两边用同一份训练代码。原来 PhysX 用的 PPO 代码里，约束动作均值的那一项写法有误（对所有动作均值都有一个很小的、朝同一方向的拉力），mortar 这边一开始就用了改正后的写法，所以 PhysX 也用改正后的写法重跑了一遍。原写法下 PhysX 的结果（“PhysX 拧瓶盖”一节里的那一批）：转满一圈，不给触觉 8.3–71.6 %，二值 86.3–91.1 %，原始触觉 90.4–92.7 %，CNN 84.8–91.9 %。那一批里有训练末尾回报崩掉的：不给触觉种子 1（回报最高到过 416，在 28.8 百万步之后掉到 17）；评测用的是训练结束时的检查点。

“提起”这一步两边不一样。mortar 已评测的 17 次训练里有 3 次（二值接触（种子 0）、CNN（种子 0）、不给触觉（种子 1））能拧开盖子，却几乎从不把它提起来，而是继续转（这几次的平均圈数 1.69–2.10，其余各次在 1.2–1.6 之间）；PhysX 的 17 次里没有这样的情况。奖励规则两边相同（拧开之后转动不再给奖励，提起才给），mortar 里其余几次也能提起（最高 81.2 %），所以不是提不起来，而是这几次训练没有学到这一步；为什么 mortar 里更容易停在这个做法上，没有查。

一个环境步是一个控制步（0.05 秒），包含 12 个物理步；计时包含观测、奖励和策略更新。每次训练独占一张同型号的显卡（mortar 有一次所在的显卡上间歇有别的评测任务；加跑的种子不计入速度）。mortar 用单精度，每个物理步的牛顿迭代上限设为 20。PhysX 的速度取自第一批训练（其中一次是前一天和别的任务共用显卡时跑的，每秒 1.0 万步，没有计入）；用改正后的训练代码重跑的那一批和评测共用显卡，也没有计入。迭代上限对 mortar 的速度影响很大（每个物理步所有环境要等最慢的那个）：随机动作的单独测试里（改正复位之前测的），上限 60、20、10 时每秒 2182、3353、4034 步。

mortar 比 PhysX 慢约 6.4 倍。两边的解法不同：mortar 每个物理步把接触和关节一起迭代到收敛（隐式求解，这里最多 20 次牛顿迭代），PhysX 每步用固定的 8 次迭代。

同一个检查点，不再训练，各 1026 个环境 × 一个回合。PhysX 训练的策略是用改正后的训练代码重跑的那一批，放进的是改正复位之后的 mortar。

PhysX 训练的策略放进 mortar：不给触觉的策略转满一圈从 71.2–81.6 % 降到 33.9–64.9 %，CNN 从 88.2–93.8 % 降到 18.8–63.6 %，二值和原始触觉从 85.4–96.5 % 降到 2.7–50.5 %。按保留的比例算，不给触觉是原来的 43–80 %，CNN 是 21–68 %，二值和原始触觉只有 3–59 %。直接读触觉数值的两种输入掉得最多；两边触觉读数的大小不同（PhysX 的指垫是软的，同样的力压入更深）是原因之一，验证见下面。反过来，mortar 训练的策略放进 PhysX：不给触觉从 75.3–88.9 % 变成 3.0–47.1 %；二值接触从 85.9–91.9 % 变成 1.1–32.5 %；原始触觉从 67.8–93.2 % 变成 18.7–58.3 %；CNN 从 85.9–94.6 % 变成 1.5–62.6 %（转满一圈）。这个方向上，大多数回合是因为松手提前结束的（52.4–95.0 %）。松手规则数的是“有几根手指的指垫压着盖子”，而这个数两边本来就不同（保持抓握时 PhysX 平均 1.41 根，mortar 1.73 根，见下一小节）；这可能是原因，没有单独验证。

为什么读触觉数值的策略掉得最多，做了一个单独的验证。两边指垫的软硬不同（见还不一样的地方），同样的抓握，mortar 里的触觉读数只有 PhysX 的几分之一。测试：物理不动，只把 mortar 里的触觉读数乘一个系数再交给同一个 PhysX 策略。

缩小读数后成功率从 39.1 % 升到 62.9 %，但松手提前结束的回合仍然占大多数：读数大小只是一部分原因。

两个版本对不对得上：同一段动作脚本

做了什么：不用策略，在两个仿真器里执行同一段固定的动作：按抓握姿态保持 2 秒，把手张开，保持，合回去，保持，再捏紧，保持；关掉“松手就结束”的规则，1026 个环境。逐段比较关节跟指令跟到什么程度、关节力矩多大、指尖压进盖子多深、几根手指压着盖子、盖子被带着转了多少。

靠这个对比查出了第一版的三处差别：

  • PhysX 版的手其实有两套位置控制。除了任务自己按指令算的那一套，手的执行器模型里还有一套，一直把每个关节往回合开始时的抓握姿态拉。两套叠在一起，手在没有阻挡时只走到指令的一半：实测 PhysX 里各关节跟上指令变化的比例中位数是 0.50；第一版的 mortar 里是 1.0，手听话得多，任务也就容易得多。补上第二套后 mortar 是 0.48。
  • 摩擦设得太软。mortar 的摩擦在滑动很小时像一根弹簧，它的刚度是一个单独的设置，第一版用的默认值比接触刚度软 30 倍，手指要在盖子上多滑一截才有足够的摩擦力：张开手时盖子几乎不被带动，捏紧时手指从盖子上滑开。调到和接触刚度相同。
  • 手指之间、手指和手掌之间的碰撞没有开。补上前两处之后，捏紧阶段 mortar 的关节力矩平方和仍只有 PhysX 的五分之一左右（3.6 对 16.6）；把 PhysX 的手自碰撞关掉再测，它也降到 4.7，说明差的就是这一项。按 PhysX 的规则打开（有关节直接相连的连杆之间不碰，其余都碰）之后，mortar 是 12.5。

更早还有一处：第一版沿用了我们给人形机器人用的关节约束刚度，对这只手不合适（拇指里有一个只有 0.08 克的连杆），手在重置后只动一步就不再动；改用 mortar 默认的刚度后正常。这一处是从“关节不跟指令”直接看出来的。

第四处（11-22 中午查出）：回合开始时手指嵌在瓶盖里。每个回合从预先存好的抓握姿态开始。这些姿态是给“手里握着一个自由物体”的任务生成的，而这里瓶盖固定在螺纹上、还带一个随机的转角，所以手指的初始位置常常和瓶盖重叠：复位的那一刻，46 % 的环境里有一根手指的指垫嵌在瓶盖里 8 毫米以上。PhysX 会在第一个控制步里把重叠的手指推出来，手指随后靠位置控制压在盖子表面上；mortar 的接触是从表面外侧开始算的，一开始就嵌得很深的手指约有一半一直留在里面，几乎不受力。结果是改正前的 mortar 版里，回合开始 2 秒后仍有 24 % 的环境有手指嵌在盖子里，全手的力矩平方和只有 PhysX 的四分之一（0.13 对 0.55）：手握得比 PhysX 松得多。

改法：复位时先把嵌在盖子里的那根手指张开到刚好不重叠，位置指令仍然是存好的抓握姿态，于是手指从外面压回到盖子上，和 PhysX 推出来之后的状态一样。改正后各手指的受力和 PhysX 对上了：

两个版本还不一样的地方

  • 指垫的软硬。PhysX 里五个指尖软垫用的是“柔顺接触”（很软），金属连杆是硬接触；mortar 这一版把手当成刚体，所有接触用同一个刚度。保持抓握时拇指指垫压进盖子的深度，PhysX 是 3.0 毫米，mortar 是 0.6 毫米。这个刚度当初是按“随机动作下最深压入的平均值和 PhysX 接近”选的，后来发现那个平均值被嵌在盖子里的手指抬高了（上面的第四处），所以这个选法不成立；我们试过把刚度调软 3 倍（在改正复位之前），捏紧时有近两成环境的手指穿进盖子，所以没有再调软。mortar 可以把指垫做成可变形体（它在别的任务里就是这么用的），这一版没有做。
  • 触觉信号。两边都用同一个公式从指尖位置算压入深度，但因为上一条，mortar 里的读数比 PhysX 小（保持抓握时拇指 0.6 对 3.0 毫米，中指 0.7 对 1.1 毫米）。
  • 回合开始时的状态。见上面的第四处：受力对上了，但食指、小指的接触部位和盖子被带动的角度还有差别。
  • 关节摩擦。手的模型文件里每个关节有摩擦参数，mortar 这一版没有带过去。
  • 手掌。mortar 这一版把手掌当作固定不动的外形（手本来就是固定在空中的）。

条件

  • 任务：27 种瓶盖（9 种形状 × 3 种大小），盖子套在螺纹上，转满 1.5 圈脱离，之后要提起；每个回合 20 秒，从预先存好的抓握姿态开始。控制 20 Hz，物理步长 1/240 秒。
  • 训练：PPO，4104 个环境，每次 3000 万步，两边同一份代码和超参数；价值网络另外能看到盖子的状态，策略网络看不到。
  • 触觉输入四种：不给触觉、二值接触、原始触觉（每指 32 个点的压入深度，8 帧）、CNN（同样的数据先过一个小卷积网络）。冻结的 LingBot-Touch 编码器这次没有在 mortar 里跑。
  • 机器：两边都是同型号的显卡，每次训练独占一张。
  • 这是仿真之间的对比，没有真机实验。
