Wan2.1-I2V-14B 的技术架构

VPP2 的视频底座是 Wan2.1 的图生视频 14B 模型（480P 版本）。这一页把它拆开：视频先被 Wan-VAE 压成 latent，再切成 token 送进 40 层扩散 Transformer，文本靠 umT5 走交叉注意力，条件图片同时从通道拼接和 CLIP 上下文两条路进来，训练目标是流匹配。参数量用权重文件的大小对了一遍账。技术报告见 arXiv 2503.20314，代码见 GitHub。

1. 一次图生视频的全景

  1. 文本编码。提示词进 umT5-XXL 编码器（约 5.7B 参数，只用编码器），得到最多 512 个文本 token。选它而不是 LLM 的原因：多语言、双向注意力，报告里说这对扩散任务更合适。
  2. 条件图片两条路。第一条：图片在时间轴上和零帧拼在一起，经 Wan-VAE 编码成条件 latent，再和一个标记"哪几帧是给定的"的二值 mask 一起沿通道拼到噪声 latent 上。第二条：图片过 CLIP 图像编码器（OpenCLIP 的 XLM-RoBERTa-Large + ViT-H/14），特征经三层 MLP 变成全局上下文，通过解耦的交叉注意力注入 DiT。
  3. 去噪。36 通道的 latent 经 (1, 2, 2) 的 3D 卷积分块成 token，加时间步调制，过 40 层 DiT，每层做一次视频 token 之间的 3D 全注意力、一次对文本（和图像上下文）的交叉注意力、一次 FFN。模型输出的是流匹配的速度场。
  4. 求解。从纯噪声出发按速度场积分，官方脚本 I2V 默认 40 步、无分类器引导系数 5；得到干净的 latent。
  5. 解码。Wan-VAE 把 latent 解回像素：480P 版本是 832×480、81 帧、16 fps 的 5 秒视频。

这五步在下面的 3D 实验 1 里是一张图：主干在中间，两条条件支路在两侧，求解器循环在左边。

2. Wan-VAE：先把视频压小 256 倍

Wan-VAE 是一个 3D 因果变分自编码器，127M 参数。输入 (3, 1+T, H, W) 的视频，输出 (16, 1+T/4, H/8, W/8) 的 latent：时间压 4 倍、空间各压 8 倍、通道扩到 16。第一帧只做空间压缩，所以帧数是 1+T/4 而不是 T/4，这也是为什么 Wan 的帧数总是 4k+1（17、49、81）。

因果
3D 卷积只看过去的帧，保证每个 latent 帧只依赖它之前的像素帧。GroupNorm 换成 RMSNorm，就是为了不破坏时间因果。
特征缓存
视频按 4 帧一块分块处理，卷积核为 3 时缓存前两帧的特征，于是任意长度的 1080P 视频都能以恒定显存编解码，历史信息不丢。
效率
报告里在 200 段 720×720、25 帧的视频上，重建速度是 HunyuanVideo VAE 的 2.5 倍，PSNR 相当。上采样层输入通道减半，推理显存降 33%。

每个 block 里发生什么

  1. 时间步调制（adaLN）。时间步 t 先做 256 维正弦编码，经 MLP 变成 5120 维，再由一个所有 block 共享的 SiLU + Linear 投影成 6 个调制向量：注意力前的 shift、scale 和之后的 gate，FFN 前的 shift、scale 和之后的 gate。每个 block 只保留自己的一组可学习偏置。报告说这比每层各一个投影省约 25% 参数。
  2. 3D 自注意力。所有视频 token 两两做全注意力，没有时空分解。位置信息用 3D RoPE：head 的 128 维里分别给时间、高、宽留出旋转分量（代码里按 128 − 4·21、2·21、2·21 划分）。q 和 k 过 RMSNorm。
  3. 交叉注意力。视频 token 当 query，umT5 的 512 个文本 token 当 key 和 value。I2V 版本在这里再多一组 k、v 投影给 CLIP 的 257 个图像 token，两路结果相加，这就是"解耦交叉注意力"。
  4. FFN。5120 → 13824 → 5120，GELU 激活。

4. I2V 的条件图片是怎么进去的

两条路，各管一头：

通道拼接：管"像素级忠实"
条件图片放在第 0 帧，后面补零帧，一起过 Wan-VAE 得到 16 通道的条件 latent。再造一个 mask：给定的帧填 1，要生成的帧填 0，按 VAE 的时间步长重排成 4 通道。噪声 latent (16) + 条件 latent (16) + mask (4) = 36 通道进 DiT。多出来的输入投影层零初始化，所以刚开始微调时模型的行为和 T2V 一模一样。
CLIP 上下文：管"语义级一致"
图片过 OpenCLIP 的 ViT-H/14（1.2B 的 CLIP 里只用视觉塔，约 0.6B），得到 257 个 token（16×16 个 patch 加一个 CLS），过三层 MLP 投到 5120 维，每个 block 的交叉注意力里用独立的 k、v 投影读它。这样首帧之外的帧也能"知道"画面里有什么。

I2V 模型从 T2V 模型初始化，分别在 480P 和 720P 两个分辨率上微调，所以有两个独立的 checkpoint。VPP2 用的是 480P 版，但把分辨率进一步降到 416×240。

5. 训练目标：流匹配

x_t = t · x₁ + (1 − t) · x₀ x₁ 是干净 latent，x₀ ~ N(0, I) 是噪声，t ∈ [0, 1] v_t = x₁ − x₀ 从噪声指向数据的恒定速度 L = E ‖ v_θ(x_t, t, c) − v_t ‖² 模型学的是速度场；t 从 logit-normal 分布采样，中间时刻采得更多

推理时从 x₀ 出发沿速度场积分到 t = 1。因为学的是"直线"，步数可以比传统扩散少，但官方默认仍然要 40 到 50 步，每一步都是一次 14B 的前向。Wan 自己的训练分三段升分辨率：先 256p 图片，再 192p 的 5 秒视频，然后 480p，最后 720p；优化器 AdamW，学习率 1e-4。这条"先直线、后多步"的路，正是 VPP2 要用一致性蒸馏压成一步的东西，见后训练过程的 3D 实验 2。

所以名字里的"14B"继承自 T2V，I2V 版本因为每层多了一组图像 k、v，实际是 16.4B。VPP2 论文里写的 VPP2-14B 也是沿用这个叫法；加上 0.9B 的动作专家，整套策略约 17.3B，再加 5.7B 的 umT5 编码器和 0.6B 的 CLIP 视觉塔。
