自建任务：触觉拧瓶盖（PhysX）

论文里的拧瓶盖是真机任务（表 2），没有仿真环境可以复现。这一节按同样的思路在仿真里自己搭了一个：Sharpa 手拧开固定在桌上的瓶子的瓶盖，用 Isaac Sim 的 PhysX 引擎训练，触觉输入的五种给法和转圆柱完全相同。目的是看冻结的官方 LingBot-Touch 编码器能不能训练出这个任务。

资产。瓶子和瓶盖来自 Berkeley 公开的 twisting-lids（“Twisting Lids Off with Two Hands”，BSD 许可）里程序化生成的 64 个瓶子，取其中 27 个，按 Sharpa 手的大小缩放（瓶盖直径 37–42 mm、高 17–27 mm）。我们没有找到公开的、带触觉的拧瓶盖仿真环境；触觉沿用前面的做法，对瓶盖的网格直接计算每个采样点的压入深度。

任务设置。

  • 瓶身固定不动；瓶盖装在一个只能绕瓶轴转动的关节上，关节带恒定的阻力矩（每个环境在 0.02–0.06 N·m 之间随机取一个），不推就不转。
  • 手从上方伸下来，指尖围住瓶盖；动作（22 个关节的目标增量）、本体感觉、PPO 设置都和转圆柱相同。4104 个环境并行（27 个瓶子各 152 个）。
  • 瓶盖不会掉，所以“掉落”换成“松手”：压在瓶盖上的指尖少于 2 个、持续超过 0.5 秒，回合结束。
  • 奖励 = 瓶盖朝拧开方向的转速 − 力矩、做功等惩罚 + 不松手的小额奖励。价值网络额外能看到瓶盖的半径、高度和阻力矩（只在训练时用）。
  • 评测：1026 个回合，每回合 20 秒，看松手之前瓶盖转过多少圈。

实现上的一个说明：仿真里是把整个场景倒过来算的（手在下、瓶子在上、重力方向取反），渲染出的画面再转 180°。这样可以原样复用转圆柱环境里手的位置和初始抓取姿态，物理上和“手在上、瓶子在下”等价。

这个动作是怎么来的：人定了什么，PPO 学了什么，触觉怎么进去

手指怎么动不是设计出来的，是 PPO 从零学出来的。没有示教，没有预先写好的轨迹或动作模板；策略网络一开始是随机的，靠在 4104 个并行环境里反复尝试、按奖励调整。人定的只有三样：场景、起始姿势、什么算好。

谁定的具体内容
场景和物理人定瓶身固定；瓶盖装在关节上，带阻力矩；螺纹是沿瓶轴的弹簧-阻尼力；手掌固定不动，只有 22 个手指关节能动
起始姿势人定（取自 Sharpa 开源仓库附带的抓取缓存）每个回合开始时手指已经围在瓶盖周围：从 5 万个握住圆柱的手指姿势里随机取一个，瓶盖的朝向也随机。策略没有学“伸手去够”和“抓住”这两步
奖励（什么算好）人定拧开之前奖励瓶盖朝拧开方向的转速，拧开的一刻加 10 分，拧开之后奖励提起的高度；力矩和做功有小额惩罚；松手则回合结束。另外有一条从转圆柱环境留下来、我没有关掉的规则：瓶盖被提到螺纹顶端以上约 14 mm 时回合也会结束
每一步手指怎么动PPO 学策略网络每 0.05 秒输出 22 个关节目标角度的增量。哪根手指什么时候推、怎么换指、往瓶口压还是往外带、拧开后怎么把瓶盖提住，都是学出来的
从触觉信号里提取什么PPO 学（CNN 输入时）CNN 和策略一起训练。换成 LingBot-Touch 时编码器是冻结的官方权重，只训练它后面的小读出层

怎么知道是学出来的。两种奖励设置的对比就是证据：代码、起始姿势、随机种子都一样，只改了奖励里的一个数，学出来的动作就从“往外带着转、拧开后提起”变成了“压着转、拧开后接着空转”。更早的时候还没有“松手即结束”这条规则，策略学成了把手指挪开、什么都不做。

PPO 是怎么训练的。4104 个环境（27 个瓶子各 152 个）同时仿真，每个环境每 0.05 秒走一步。每走 8 步，把这 3.3 万条“看到了什么、做了什么、得了多少奖励”的记录拿来更新一次网络，再用新的网络接着试。一共 3000 万步、约 910 次更新，相当于 417 小时的仿真经验；CNN 输入的这次在一块共用的显卡上约 50 分钟。策略网络是三层全连接（512、256、128 个单元），输出 22 个动作的均值，训练时在均值上加随机扰动来探索。数据流和转圆柱完全相同，见五种触觉输入怎么接进策略里的图。

触觉信息是带着的。每个指尖的触觉区域上有 32 个采样点，五个指尖共 160 个。每个点的数值是“瓶盖压进指尖多深”，由指尖的位姿和瓶盖的网格直接算出来，0 表示没碰到，再按真实传感器的输出格式量化到 0–255。策略每一步收到最近 8 帧（0.4 秒）：CNN 把这 8 × 160 个数压成 64 个数，和关节信息拼在一起送进策略网络。五种输入只是这一步的给法不同：不给、只给碰没碰到、原样给、过 CNN、过冻结的 LingBot-Touch 编码器。

策略看不到的东西。瓶盖转了多少、有没有脱开、升起多高、瓶盖多大、阻力矩多大，策略都看不到，这些只给训练时用的价值网络。它只有最近 3 步的手指关节角度、关节目标和指尖触觉，“瓶盖松了没有”只能从这些里感觉出来。

“带着触觉”不等于“用上了触觉”。目前的证据：

  • 不带螺纹的版本用不上触觉：完全不给触觉的策略一样能拧（96.8 % 转满 2 圈）。
  • 带螺纹、要提起的版本里，触觉有帮助：拧开并把瓶盖提到高过瓶口的比例，不给触觉 80.3 / 93.2 / 69.9 %（平均 81.1 ± 11.7），带触觉的四种是二值接触 99.1 / 96.1 / 94.3 %（平均 96.5 ± 2.4）、原始信号 97.0 / 97.0 / 68.2 %（平均 87.4 ± 16.6）、CNN 98.1 / 99.5 / 94.2 %（平均 97.3 ± 2.7）、LingBot-Touch 98.2 / 0.0 / 98.8 %（平均 65.7 ± 56.9）。差别主要来自松手：不给触觉 14.7 / 5.8 / 27.0 %（平均 15.8 ± 10.7），带触觉的除了原始信号的一个种子以外都在 3 % 以内。但带触觉的四种之间分不出高下。
  • 反过来的例子也有：“只转不提”的那个策略同样带着触觉输入，瓶盖脱开时它的动作没有任何变化。

仿真里的触觉是按几何算出来的压入深度，不是对软指尖形变的物理仿真：PhysX 里指尖是刚体，“压入”是指尖采样点和瓶盖网格的重叠量。真实传感器的噪声、延迟和滞后这里都没有。指尖触觉区域以外的部位（比如指侧）碰到瓶盖，触觉里是看不到的。

目前能说的。

  • 用冻结的官方 LingBot-Touch 编码器能训练出拧瓶盖，而且这一次是五种输入里最好的。训练 3000 万步后，99.7 % 的回合转满 2 圈、81.2 % 转满 3 圈，平均 3.64 圈；其余四种转满 2 圈的比例在 93.8–97.1 %，转满 3 圈在 54–72 %，平均 3.05–3.37 圈。
  • 但差距不大，而且每种输入只有一个种子，还不能下“触觉编码器更好”的结论。转圆柱的结果已经说明同一设置换个种子差别可以很大；这里五种输入的另外两个种子已经排上，跑完再比较。
  • 当前这个版本的任务不依赖触觉。完全不给触觉输入的策略同样学会了：96.8 % 的回合转满 2 圈、平均 3.37 圈，比二值接触、原始信号、CNN 还多一点。原因大概是瓶盖的位置固定、阻力矩小，手指按固定的节奏拨就能转起来；手指有没有碰到瓶盖，从关节“目标角度和实际角度的差”里也能间接看出来。
  • 这个任务在 PhysX 里学得很快：CNN 输入训练 1200 万步（约 15 分钟）就已经和训练 3000 万步时差不多。
  • 训练过程中踩过一个坑：最初没有“松手即结束”这条规则，策略学成了把手指挪开、什么都不做，因为那样没有任何代价。

还没做的和局限。上面这个不带螺纹的版本每种输入只有一个种子；瓶身只有外观、没有碰撞，阻力矩取得偏小。要让各种触觉输入之间真正拉开差距，还需要瓶子的位置和瓶盖的大小在每个回合里随机偏移、阻力矩加大并随机变化。

加上螺纹：拧开之后把瓶盖提起来

上面的版本里瓶盖只是在原地转，转多少圈都不会升起，也拿不下来，看不出“拧开了”。所以又做了一个带螺纹的版本：

  • 瓶盖每转一圈沿螺纹上升 4 mm；转满 1.5 圈（上升 6 mm）后和瓶口脱开。
  • 脱开以后瓶盖可以沿瓶轴自由移动，重力会把它拉回瓶口，除非手指把它提住。
  • 成功 = 拧开，并把瓶盖提到高过瓶口（螺纹顶端以上 5 mm），一直保持到回合结束。最初定的线是 10 mm，后来发现它和奖励的封顶点重合，不适合用来比较（见下面结果里的说明），表里两条线都列出来。
  • 奖励：拧开之前奖励转速，拧开的那一刻有一次性奖励，拧开之后奖励提起的高度；“松手即结束”的规则不变。

实现上的说明：螺纹是一个沿瓶轴方向的弹簧-阻尼力，每个物理步施加一次；瓶盖只能绕瓶轴转动和沿瓶轴移动，不会倾斜或横移，所以“提起”是沿瓶轴提起。手掌的位置是固定的，提起完全靠手指，行程只有一两厘米。

结论（15 次训练和两种方式的重新评测都已完成）。

  • 用冻结的官方 LingBot-Touch 编码器能训练出“拧开并提起瓶盖”，但三个种子里有一个没学会提。拧开并把瓶盖提到高过瓶口的比例：98.2 / 0.0 / 98.8 %（平均 65.7 ± 56.9）。种子 0 和种子 2 都在 98 % 以上；种子 1 学成了只拧不提：99.3 % 的回合拧开，却没有一次把瓶盖提起来，整个训练过程里也从没出现过提起。这和转速奖励上限设错的那一次是同一种现象：瓶盖脱开后落回瓶口，要再升高 6 mm 以上才开始有提起奖励，策略一旦停在“只转”上就得不到往上提的信号。四种基线的 12 次训练里没有出现这种情况。三个种子里出现一次，还说明不了官方编码器更容易这样，但也不能说它稳定。
  • 触觉有用，而且是用在“提住”上。五种输入都能拧开（已完成的 15 次训练在 94.7–99.7 % 之间）。拧开并把瓶盖提到高过瓶口的比例：不给触觉 80.3 / 93.2 / 69.9 %（平均 81.1 ± 11.7）；带触觉的四种是二值接触 99.1 / 96.1 / 94.3 %（平均 96.5 ± 2.4），CNN 98.1 / 99.5 / 94.2 %（平均 97.3 ± 2.7），LingBot-Touch 98.2 / 0.0 / 98.8 %（平均 65.7 ± 56.9），原始信号 97.0 / 97.0 / 68.2 %（平均 87.4 ± 16.6）。差别主要来自松手：不给触觉 14.7 / 5.8 / 27.0 %（平均 15.8 ± 10.7）；二值接触 0.2 / 0.1 / 2.8 %（平均 1.0 ± 1.5）；CNN 0.1 / 0.2 / 2.5 %（平均 0.9 ± 1.4）；LingBot-Touch 0.8 / 0.4 / 0.9 %（平均 0.7 ± 0.3）；原始信号 2.0 / 1.6 / 20.4 %（平均 8.0 ± 10.7）。不给触觉的策略多数是把瓶盖提起来以后又松开的，它没有办法知道手指还有没有压在瓶盖上。
  • 带触觉的四种输入之间分不出高下。除了两次没学好的训练（原始信号的种子 2 有两成的回合松手；官方编码器的种子 1 只拧不提），带触觉的各次训练都在 94 % 以上，不同输入之间的差距比同一种输入换个种子的波动还小。原始信号换个种子不稳定，这在转圆柱时也出现过（三个种子 60.9 / 7.0 / 87.0 %）。也就是说，这个任务对带触觉的策略已经接近满分，没有区分度：它能说明“用官方编码器可以训练出这个任务”和“触觉有用”，但不能说明哪一种触觉表示更好。要比较，需要更难的版本，见下面瓶盖形状和大小各不相同的版本。
  • 去掉高度限制再评测，结论一样。把瓶盖提到高过瓶口并一直拿到 20 秒结束的比例：不给触觉 77.4 / 88.7 / 61.1 %（平均 75.7 ± 13.9）；二值接触 98.9 / 94.6 / 91.6 %（平均 95.1 ± 3.7）；原始信号 96.3 / 96.5 / 32.8 %（平均 75.2 ± 36.7）；CNN 96.5 / 99.5 / 93.5 %（平均 96.5 ± 3.0）；LingBot-Touch 97.3 / 0.0 / 97.6 %（平均 64.9 ± 56.2）。
  • 更正两处我之前的统计。第一，我把“回合提前结束”都标成了“中途松手”，这不对：带触觉的策略提前结束的回合，多数是把瓶盖提到了螺纹顶端以上约 14 mm，碰到转圆柱环境留下来、我没有关掉的高度限制。这种情况其实是提起来了，却被算成了失败。第二，我原来定的成功线（提到 10 mm 以上）正好是提起奖励封顶的位置，各个策略都把瓶盖停在 10 mm 上下（结束时平均在螺纹顶端以上 -6.4–11.0 mm），差零点几毫米就从成功变成失败，同一种输入换个种子能差十几个百分点。所以把所有策略重新评测了一遍：分开统计松手和被截断，并且去掉高度限制再评测一次。原来的数字收在表下面的折叠栏里。

进度。五种触觉输入各训练 3000 万步、各三个随机种子：四种基线的种子 0 已完成，种子 1、2 和冻结的官方 LingBot-Touch 编码器的三个种子（每次约 3.3 小时）在两台机器上进行，预计 11-19 早上全部完成。这组训练在 11-18 23:21 重新开始过一次：第一次我把转速奖励的上限从 0.5 rad/s 提到了 1.5 rad/s，想让它拧得更快，结果 CNN 那次学成了只顾快转，99 % 的回合拧开了瓶盖，但没有一次把它提起来（画面、统计和原因见下面的对比）。现在用的是 0.5 rad/s，和上面预览用的试训练一致。

第一次的设置是什么效果：只转不提（转速奖励上限 1.5 rad/s）

正式训练一开始，我把转速奖励的上限从 0.5 rad/s 提到了 1.5 rad/s，想让策略拧得更快。那次训练（CNN 输入，3000 万步）在 1026 个回合的评测里 99.0 % 拧开了瓶盖，但没有一次把它提起来。它的策略文件还在，下面把它和改回 0.5 rad/s 之后的策略放在同样的瓶子上回放。两次训练只有这个上限不同，其余设置和随机种子都一样。

怎么读。

  • 第一次的策略确实把瓶盖拧开了，但拧开前后它的动作没有任何变化。瓶盖脱开前后的转速一样（1.44 和 1.43 rad/s），20 秒里一共转了 4.7 圈左右；瓶盖脱开后落回瓶口，在瓶子上空转。评测里的“拧开 99 %、提起 0 %”就是这个画面。
  • 两种策略拧的速度差得不多，差别在手指沿瓶轴往哪个方向用力。第一次的策略是把瓶盖往瓶口方向压着转：还在螺纹上的时候，瓶盖比螺纹应有的高度低 1.7 mm，一脱开就落回去。改回之后的策略是往外带着转：瓶盖比螺纹应有的高度高 1.7 mm，螺纹一松开，瓶盖就被带起来。
  • 训练过程里也看得到。第一次的训练中，处在“提起到位”状态的环境比例在 3000 万步里从没超过 0.9 %，训练结束时每回合的奖励约 455，几乎全部来自拧的阶段。改回之后的训练在约 690 万步时这个比例超过 5 %，结束时约 40 %（这是任一时刻的比例，回合的前一段还在拧，所以低于评测的成功率），每回合的奖励约 816。
  • 为什么上限一改就学成这样。这一条是解释：两种设置各只训练了一次，没有用更多随机种子验证。转速项每一步的奖励是 2.5 × 转速，超过上限的部分不算；提起项每一步最多 3.0。上限是 1.5 rad/s 时，全速转每一步能拿 3.75，比提起之后每一步最多能拿的还多，拧的阶段本身就是整个回合里奖励最高的部分，策略学到的是怎样转得最快。而且瓶盖一旦落回瓶口，要再升高 6 mm 以上才开始有提起奖励，中间没有任何信号告诉它该往上提。上限是 0.5 rad/s 时，转速项每一步最多 1.25，不到提起项的一半，尽早拧开、然后把瓶盖提住才是奖励最多的做法。
  • 更正我之前的一句话。我原先写的原因是“转得越快越带不住”，这个说法不准确：两种策略脱开之前的转速只差 25 %（1.44 对 1.15 rad/s），改回之后的策略也远快于 0.5 rad/s。真正的差别是上面说的压着转还是带着转。

模型上的一个简化会让上排看起来比真实情况更顺：瓶盖脱开以后螺纹不再起作用，落回瓶口时不会重新旋上，所以能一直空转。表和图只来自这两段回放（各 27 个回合）；1026 个回合的评测结果见上面的表。

瓶盖的形状和大小各不相同的版本

上面那 27 个瓶子看起来几乎一样（瓶盖都是直径 37–42 mm 的圆盖），而且对带触觉的策略来说已经接近满分，分不出几种触觉输入的高下。所以又做了一个版本：九种形状 × 三种大小的 27 个瓶盖，每种形状配一个颜色和瓶身形状都不同的瓶子。

和上一个版本相比改了三处。

  • 瓶盖：形状和大小不再相近，三棱柱、圆台这类不好抓的形状也在里面。
  • 去掉了转圆柱环境留下来的高度限制，回合只会因为松手提前结束。
  • 提起的奖励一直加到螺纹顶端以上 15 mm，成功线定在它下面：成功 = 拧开，把瓶盖提到高过瓶口（5 mm），并且一直拿到 20 秒结束。螺纹（1.5 圈、每圈 4 mm）、阻力矩（0.02–0.06 N·m）、松手的判定和训练步数都没变。

结论（五种输入各三个种子，15 次训练全部完成）。

  • 这个版本确实更难，几种输入之间拉开了差距。拧开、把瓶盖提到高过瓶口并拿到结束的比例：不给触觉 39.8 / 43.7 / 21.1 %（平均 34.8 ± 12.1）；二值接触 61.7 / 58.6 / 85.4 %（平均 68.6 ± 14.7）；原始信号 68.3 / 84.8 / 76.9 %（平均 76.7 ± 8.2）；CNN 86.1 / 76.1 / 86.7 %（平均 83.0 ± 5.9）；LingBot-Touch 81.4 / 74.6 / 73.9 %（平均 76.6 ± 4.2）。上一个版本里带触觉的几种都在 94 % 以上，分不出高下。
  • 差别还是主要来自松手。松手的比例：不给触觉 50.7 / 35.4 / 53.3 %（平均 46.5 ± 9.7）；二值接触 28.4 / 36.0 / 8.9 %（平均 24.4 ± 14.0）；原始信号 17.9 / 11.3 / 9.1 %（平均 12.8 ± 4.6）；CNN 9.8 / 13.6 / 6.2 %（平均 9.9 ± 3.7）；LingBot-Touch 14.2 / 12.5 / 6.8 %（平均 11.2 ± 3.9）。
  • 不同形状之间差别很大。三棱柱对哪种输入都最难，圆台和椭圆柱其次，圆柱、五棱柱、六棱柱、鼓形最容易（见下表）。
  • 四种基线各三个种子都跑完了，顺序和九物体转动任务上一致。不给触觉 < 二值接触 < 原始信号 < CNN：给策略的触觉信息越多，成功率越高。但相邻两种之间的差距和它们各自换种子的波动差不多大（二值接触最好的种子 85.4 % 已经超过 CNN 最差的种子 76.1 %），能确定的只有“不给触觉明显最差”。
  • 冻结的官方 LingBot-Touch 编码器没有比 CNN 好。它的三个种子是 81.4 / 74.6 / 73.9 %（平均 76.6 ± 4.2），和原始信号（68.3 / 84.8 / 76.9 %（平均 76.7 ± 8.2））差不多，比 CNN（86.1 / 76.1 / 86.7 %（平均 83.0 ± 5.9））低 6 个百分点，差距在换种子的波动范围内。它的三个种子比较集中，这一点和转单个圆柱时一样。也就是说，在这个更难、几种输入能拉开差距的任务上，冻结的预训练编码器仍然没有显出优势，这和转圆柱、转九种物体的结论一致，和论文“好于 CNN”的说法不一致。
